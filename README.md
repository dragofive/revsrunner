# custom-ios-runner

Отдельный репозиторий, который Codemagic клонирует для каждой iOS-сборки
пользовательского проекта в модуле Custom Builds (BYO). В отличие от
`ios-template` (фиксированная Capacitor-оболочка «сайт в приложение»), этот
раннер собирает СОБСТВЕННЫЙ проект пользователя: Flutter / React Native / Expo /
Capacitor / нативный Xcode.

Ничего специфичного для тенанта тут не хранится: исходники и Apple-ключ
приходят per-build через `environment.variables`, которые задаёт бэкенд RevsApp.
Один раннер обслуживает всех пользователей.

## Что делает воркфлоу `custom-ios`

1. `scripts/download-source.sh` - скачивает ZIP исходников по `REVS_SOURCE_URL`
   (presigned) и распаковывает в `./src`.
2. `scripts/sign.sh` - получает/выпускает distribution-сертификат и профиль через
   App Store Connect API по ключу `.p8` тенанта. **Без revoke** чужих
   сертификатов (автопилот, безопасно для аккаунта, которым пользователь
   подписывает и сам).
3. `scripts/build.sh` - prebuild по типу проекта (`flutter build ios` /
   `pod install` / `cap sync` / `expo prebuild`), находит `.xcworkspace`/
   `.xcodeproj` и схему, собирает `.ipa` и нормализует его в `build/ios/ipa/`.
4. `scripts/notify-backend.sh` - шлёт итог на `POST /api/custom/ios/webhook`,
   подписанный per-build HMAC-ключом (`REVS_WEBHOOK_TOKEN`).

## Разовая настройка

1. Создайте **приватный** GitHub-репозиторий (например `custom-ios-runner`) и
   запушьте туда содержимое этой папки (`codemagic.yaml` + `scripts/`). Никаких
   секретов тут нет.
2. В Codemagic: Applications → Add application → выберите этот репозиторий. Ключ
   доступа (`CODEMAGIC_API_TOKEN`) уже используется бэкендом, отдельный проект в
   UI регистрировать не нужно - бэкенд создаст Codemagic-приложение сам при
   первой сборке (дедуп по URL репозитория).
3. В `.env` бэкенда задайте:
   ```
   CUSTOM_IOS_RUNNER_REPO_URL=https://github.com/<you>/custom-ios-runner.git
   CUSTOM_IOS_WORKFLOW_ID=custom-ios
   ```
   (переиспользуются существующие `CODEMAGIC_API_TOKEN`,
   `CODEMAGIC_WEBHOOK_SECRET`, `CODEMAGIC_INSTANCE_TYPE`). Пока
   `CUSTOM_IOS_RUNNER_REPO_URL` пуст, iOS-сборки custom-проектов отвечают 503
   (фича выключена).
4. Пересоберите бэкенд, чтобы `.env` подхватился.

## Ограничение подписи (важно)

Apple ограничивает команду 3 активными distribution-сертификатами. Поскольку мы
НЕ ревокаем чужие сертификаты и каждая сборка выпускает свежий ключ, пользователь
с частыми сборками может упереться в лимит - тогда `fetch-signing-files` вернёт
409 и сборка упадёт с понятным сообщением. Пользователь освобождает слот в своём
Apple Developer аккаунте (Certificates → отозвать неиспользуемый). Переиспользование
одного сертификата на проект (чтобы снять это ограничение полностью) - тема
отдельного слайса.

## Заметки

- Это первый рабочий вариант. Реальные проекты разнообразны (монорепо,
  нестандартные схемы, кастомные `ExportOptions`), поэтому скрипты, скорее всего,
  будут дорабатываться по мере тестов на настоящих сборках - как и Android-движок
  отлаживался по стадиям на реальных сборках.
- Публикация в TestFlight/App Store здесь НЕ включена (только сборка и скачивание
  `.ipa`). Это отдельный слайс.
